# RunForge

RunForgeは、実行結果の微調整を行うためのWindows用ツールです。実行結果が保存されたフォルダを開くと、保存されているすべてのサンプルを表示し、その結果に基づいてレポートを作成し、ローカルモデルに作業環境を提供します。作業環境では、モデルは独自の数式ツールを作成し、各パラメータが何をするのかを提案し、結果が明確になるまで複数のフォルダにわたって証拠を収集します。

RunForgeは、トレーニング記録を読み込みます。ただし、トレーニングは行いません。モデルをダウンロードしたり、PyTorchをインストールしたり、クラウドモデルを呼び出したりすることはありません。

## レポート

`run-config*.json`ファイルのフォルダを開きます。ファイルは、フォルダ自体またはそのサブフォルダに配置できます。RunForgeは、リサンプリングを行わずに、保存されているすべてのサンプルを表示し、ギャップはギャップとして保持します。`training_summary.final_loss`は、曲線上の点ではなく、曲線に隣接するマーカーであり、レポートはそれに基づいてランキングを行いません。

レポートは、まず「要するに」という見出しで始まり、実行結果が成功したかどうか、そしてその理由を説明します。1つのレシピに対して5つの異なるシード値を使用した場合、レポートは次のように表示されます。

> どの実行結果も成功していません。シード512は、最も低い値（エポック3で0.0674）を示し、シード1024は、最も低い値の周辺で最も安定した値（0.3474）を示し、シード512の最も低い値の周辺（0.4041）と比較すると、より安定しています。各実行結果の中間値は、0.1508以内に収まっており、最も安定した実行結果の中間値の半分（0.1133）よりも広く、最も変動の大きい実行結果（0.3238）よりも狭くなっています。実行結果は部分的にしか分離されていません。

その後、レポートには以下が示されます。
- 実行結果
- 成功した実行結果、または成功しなかった実行結果の理由
- 変更された点と変更されなかった点
- 同じレシピの以前の評価
- 次に行うこと
- レポートでは説明できないこと
- 各数式の起源

何も言及する必要がないセクションは表示されません。すべての実行結果で同じ設定だった場合は、テストされていないものとしてリストされ、パラメータとして扱われることはありません。ペインと「レポートを保存」には、同じテキストが表示されます。

## 作業環境

「質問」ボタンを押すと、ローカルモデルが5つのツールを使用して実行結果を調査します。数式を測定し、変更されたパラメータを比較し、新しいツールを作成し、仮説を提案し、最後に結果をまとめます。プログラムは、すべての結果を計算し、数値を含むすべての文を書き出します。モデルは、何を見るべきかを選択し、それを言葉で表現します。モデルの最終的な注釈は、測定値ではなく、モデル自身の言葉としてラベル付けされます。

**モデルが作成するツール。** ツールは、各実行結果に対して1回評価される小さな言語で記述された数式です。例：
- `last / low`：曲線が最も低い値からどれだけ上昇するか
- `slope_between(end_epoch - 1, end_epoch)`：最後のエポックがどれだけ急峻か
- `knob('lora_r')`：レシピの値

数式は、ファイルを読むこと、ネットワークを開くこと、コードを実行することはできません。新しいツールは、すべての実行結果で値が生成され、重複していない場合にのみ保持されます。2番目のフォルダで使用されるまで、一時的なものとして扱われます。後続の数式は、名前を使用してそれを利用できるため、ライブラリはデータとともに拡張されます。ペインの数式ボックスで、自分で数式を試すことができます。

**パラメータに関する仮説。** 仮説は、パラメータ、数式、および方向を記述します。例：「LoRAランクが上がると、`last / low`は下がります」。仮説のテストは、提案されたときに固定されます。各フォルダで、プログラムは、仮説を次のいずれかに分類します。
- テストできない：パラメータが変更されていない
- 影響が複合的：他のパラメータも同時に変更された
- 結論が出せない
- または、それらの実行結果のみに基づいて結果が得られる

実行結果から仮説を検証できない場合、RunForgeは、次の条件を満たす最小限の実行結果を計画します。1つのパラメータ、2つの設定、および各設定に対して3つ以上のシード値。ただし、それらの実行結果を開始することはありません。

**複数のフォルダにわたる証拠。** 各フォルダは、e値を提供します。これは、パラメータが何の効果も持たない場合に平均して正確に1になる証拠の尺度であり、そのため、複数のフォルダにわたって乗算しても有効性が損なわれません。次の2種類のフォルダは除外されます。
- RunForgeが仮説が登録されたときにすでに見ていた実行結果を含むフォルダ
- すでにカウントされた実行結果

支持または反証された結論は、5つの新しいフォルダごとに1回、チェックポイントでのみ提示されます。各チェックポイントでは、ベンチ上のすべての仮説の双方向に対して、5％の偽陽性率でe-BHが適用されます。単一の仮説を検証するには、約3つのクリーンなフォルダで、各設定に対して3つの実行結果が必要です。この方法、そのソース、および外部レビューは、[docs/sidecar-workbench.md](docs/sidecar-workbench.md)および[docs/evidence.consult.response.md](docs/evidence.consult.response.md)に記載されています。

モデルは、`127.0.0.1:11434`上のローカルOllamaです。RunForgeは、Ollamaがツールを呼び出すことができると報告するモデルのみを使用し、クラウドタグが付けられた名前はスキップします。セッションは、最大6つのリクエストと10回のツール呼び出しに制限されます。ローカルモデルがない場合でも、レポートと数式ボックスは引き続き機能します。

## 履歴ベンチ

バックプロパゲーション`run_history.json`を含むフォルダを開くと、代わりに履歴ベンチが開きます。または、`output`ディレクトリの上のフォルダを開きます。ベンチは、実行結果をリストし、ファイル順に保存された`loss_history`を表示し、2つの行を比較し、テーブルまたは曲線をエクスポートします。

`backprop`がすでにPATHに含まれている場合、このベンチ上の「トレーニング」、「評価」、および「モデルのエクスポート」ボタンを押すと、そのコマンドが開始され、そのログが追跡されます。アプリケーションは引数を構築し、シェルを介して何も渡されません。`backprop`が見つからない場合、ボタンにはその旨が表示されます。RunForgeは、バックプロパゲーションをダウンロード、インストール、またはバンドルしません。

## 脅威モデル

**読み込むもの。** 選択したフォルダ：
- 履歴フォルダ：`run_history.json`が含まれているか、または`output/run_history.json`のサブフォルダにある
- シリーズフォルダ：`run-config*.json`が含まれており、その直接の子フォルダにも含まれている

ディスクの残りの部分を検索することはありません。また、これらのファイルに書き戻すこともありません。「エクスポート」と「レポートを保存」は、選択したパスに書き込みます。

**保持するもの。** 設定（最後のフォルダとテーマ）と`sidecar-memory.json`は、まとめて保存されます。アプリケーションがパッケージ化されている場合は、パッケージのLocalStateに、パッケージ化されていない場合は、実行ファイルの横に保存されます。メモリファイルには、フォルダパスは保存されません。保存されるのは次のとおりです。
- モデルの注釈
- 各測定された重み
- 学習された数式ツール（最大50個）
- 仮説とそのテスト結果（最大60個）
- チェックポイント

**ローカルモデルに渡されるもの。** 実行名、レシピの値、およびプログラム自身のツールの結果が、ループバックポート`11434`に送信されます。フォルダのパスは送信されません。モデルは、5つのワークベンチツールのみを呼び出すことができ、プログラムはすべての呼び出しを検証します。

**プログラムの開始時。** 「Train（学習）」「Eval（評価）」「Export（エクスポート）」のモデルの開始は、履歴ベンチのボタンが押され、プログラムがすでにPATHに設定されている場合にのみ、`backprop`で開始されます。停止すると、このウィンドウによって開始されたプロセスツリーが終了します。サイドカーはこれらのボタンを押すことはありません。

**プログラムがアクセスしないもの。** パッケージマニフェストは`internetClient`を要求しません。テレメトリやアカウントはなく、レポートの参照リストはプログラムに組み込まれています。アプリには、クラウドモデル、シェル、環境のコピー、トレーナー、モデルのダウンロードはありません。

脆弱性を報告する方法については、[SECURITY.md](SECURITY.md)を参照してください。

## ビルド

Rust 1.98.1、エディション2024。ツールチェーンファイルでバージョンが固定されています。

```bash
cargo test --locked --workspace
cargo llvm-cov --locked --workspace --all-targets --lcov --output-path lcov.info --remap-path-prefix --fail-under-lines 90
cargo run -p runforge --locked
```

カバレッジの要件：
- CIで、90%未満の行カバレッジの場合、テストは失敗します。
- Codecovは、プロジェクト全体と各プルリクエストの新しい行に対して、90%のカバレッジを要求します。

テストでは、モデルループをループバック上の偽のOllamaに対して実行します。実際のローカルモデルに対するセッションは、オプションで有効にできます。

```bash
RUNFORGE_LIVE_FOLDER=<series folder> cargo test -p runforge --features live live_workbench -- --nocapture
```
